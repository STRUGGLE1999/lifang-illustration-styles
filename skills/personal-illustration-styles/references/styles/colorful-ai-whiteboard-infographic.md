# Colorful AI Whiteboard Infographic

## Identity

- **Slug:** `colorful-ai-whiteboard-infographic`
- **Chinese name:** 彩色 AI 技术白板信息图
- **Best for:** AI 技术科普、LLM/RAG/Agent/MCP/上下文工程讲解、分阶段演进、架构图、课程讲义、博客配图、复杂概念总览
- **Mood:** 明快、教学感强、技术友好、像老师在彩色白板上把 AI 系统拆开讲清楚
- **Reference assets:** `assets/styles/colorful-ai-whiteboard-infographic/references/`

## Core Style

This style is a colorful technical whiteboard poster. It is more polished, brighter, and more diagrammatic than the warm-paper knowledge comic style. It should feel like a hand-drawn course slide or visual explainer, not a vintage notebook comic.

## Non-Negotiable Traits

- Clean white or very light paper background, sometimes with subtle off-white texture or rough paper edges.
- Big bold Chinese marker title at the top, often black with blue, green, purple, or orange emphasis.
- Dense structured layout using rounded panels, numbered sections, banners, ribbons, arrows, icons, and mini diagrams.
- Cute friendly robot mascot appears as narrator, system actor, or stage marker. The robot has glossy white body, black screen face, cyan glowing eyes, blue headset/ear details, and expressive poses.
- Bright but controlled palette: cobalt blue, purple, green, orange, yellow, red warning accents, cyan highlights.
- Hand-drawn marker/whiteboard look: thick dark outlines, slightly imperfect boxes and arrows, marker-fill shading, scribble highlights.
- Technical icons are abundant and easy to recognize: brain, database cylinder, magnifier, gear, rocket, cloud, folder, code, API, chart, warning triangle, check mark, lock, document, plug, network nodes.
- Text blocks are more structured and legible than the previous hand-drawn comic style. It may use many short Chinese explanations, numbered headings, and bullet-like rows.

## Differences From Hand-Drawn Knowledge Comic

- Use whiteboard brightness instead of warm beige paper.
- Use colorful section coding and stronger blue/purple/green/orange accents.
- Use cute robot mascots freely; they are part of the style, not drift.
- Use structured panels and technical cards more often.
- Use more icons, labels, diagrams, and table-like modules.
- Accept polished educational-poster density, while still preserving hand-drawn marker edges.

## Layout Variants

### Stage Poster

Use for one technology layer, such as LLM, RAG, Agent, MCP, or context engineering.

- Large top title with a colored stage badge, e.g. `阶段 2`, `RAG 改变了游戏规则`.
- 5-7 numbered modules arranged in a grid.
- Include one robot mascot near the title or a key module.
- Use section colors to distinguish explanation, workflow, limitations, examples, and key takeaway.
- End with a strong bottom takeaway bar or highlighted conclusion.

### Evolution Comparison Poster

Use for comparing multiple stages or systems.

- 3-5 vertical columns or side-by-side lanes.
- For technology evolution, prefer a top acronym chain such as `LLM -> RAG -> Agent -> MCP`, with each acronym in its own strong color.
- Each lane has a stage label, time range, core idea, how-it-works mini diagram, model/benefit/limitation rows, and example.
- Use large arrows between stages and a bottom “big picture” strip.
- Keep alignment crisp but hand-drawn, with rounded cards and colored borders.
- For blog overview illustrations, include a bottom capability-leap strip or one-sentence summary bar that compresses the whole evolution.

### Architecture Map

Use for showing a system stack or product architecture.

- Use layered blocks, arrows, connectors, UI/tool/data modules, central manager, and output/action modules.
- Add colorful doodles around the edges: rockets, satellites, clouds, lightning, hearts, stars, code symbols.
- Allow a playful paper-map feel with rough border and marker strokes.
- Use connectors that look hand-drawn but still trace the system clearly.

### Decision Framework Map

Use for “which layer should I use?” or “how to choose?” explanations.

- Left side lists scenarios or needs with large hand-drawn icons.
- Middle uses colored arrows flowing to recommended layers.
- Right side shows outcomes, tool clusters, or capability modules.
- It can be visually busy, with rainbow arrows, many small icons, and handwritten labels.

### Simple Architecture Diagram

Use only when content is truly narrow, such as one protocol relationship.

- White background, large simple rounded blocks, clean arrows, 2-4 colors.
- Still keep marker hand-drawn outlines and handwritten titles.
- Avoid becoming a sterile engineering diagram; add slight wobble, marker fill, and at least one small icon or mascot if appropriate.

## Article Auto-Layout Decision

When the user provides only an article, choose a layout from the content:

- Use **Evolution Comparison Poster** for articles about history, stages, generations, “from X to Y,” or multiple technologies compared.
- Use **Stage Poster** for a section focused on one concept, technology, or stage.
- Use **Architecture Map** for system structure, layers, components, context engineering, or product architecture.
- Use **Decision Framework Map** for choosing among tools, methods, layers, or approaches.
- Use **Simple Architecture Diagram** only for a narrow relationship with few elements.

If the article is long, first extract one illustration target:

1. Overall thesis.
2. The 3-5 key stages or modules.
3. The most visual metaphor: road, stack, pipeline, hub-and-spoke, classroom board, or decision map.
4. Required short labels only.

For this style, prefer richer educational posters when the article is a tutorial or technology explainer.

## Visual System

### Composition

- Use a strong title hierarchy: big black marker title, colored emphasized keywords, optional yellow ribbon subtitle.
- Break the canvas into clear colored modules with numbered circles or badges.
- Use arrows and connectors to show flow, dependencies, or evolution.
- Put a key takeaway in a bottom banner, colored brush strip, or large boxed conclusion.
- Leave enough white space between modules so the poster stays readable despite high density.

### Characters and Mascots

- Robot mascots are encouraged. Use them as guide, narrator, worker, pilot, analyst, or system avatar.
- Robot details: rounded white body, black screen face, cyan eyes, blue headphones/ears, small antenna, friendly smile.
- Human characters may appear as small users, students, engineers, or customers, with simplified cartoon faces.
- Do not use realistic humans or corporate stock characters.

### Icons and Technical Objects

- Use abundant visual shorthand: brain for model, magnifier for retrieval, database cylinder for data, gear/wrench for tools, rocket for progress, puzzle/USB/plug for protocol, cloud/API/code/folder for integrations.
- Use actual product logos only when the user asks or the article requires them; otherwise use generic icons to avoid over-branding.
- Keep icons hand-drawn with bold outlines and simple fills.

### Linework and Rendering

- Thick black or dark navy marker outlines.
- Rounded rectangles and boxes may be used, but they should look hand-drawn, not perfectly vector-straight.
- Marker shading, cross-hatching, scribble fills, and watercolor-like edge washes are acceptable.
- Use crisp readable text and icons. This style can be cleaner than the beige comic style, but not sterile.

### Palette

- Background: white, off-white, or lightly textured paper.
- Primary accents: cobalt blue, royal purple, emerald green, orange, yellow.
- Warnings/limits: red or orange with warning triangles.
- Success/benefits: green with check marks.
- Use color coding consistently across modules.

### Typography

- Big Chinese titles should look like bold marker handwriting.
- Section headings are thick, colored, and high-contrast.
- Body text is short and legible, like neat handwritten marker notes.
- Prefer concise Chinese labels over paragraphs.
- Use English acronyms visibly: `LLM`, `RAG`, `Agent`, `MCP`, `API`, `Token`, `Context`.

## Density Modes

### Default Dense Poster

Use for most article illustrations in this style.

- 70-90% canvas usage.
- 4-7 modules, many icons, color-coded headings, bottom takeaway.
- Suitable for tutorials, technical blogs, social knowledge cards, and explainers.

### Simple Diagram

Use for narrow architecture relationships.

- 40-60% canvas usage.
- 3-6 boxes or nodes with arrows.
- Keep one title, clear labels, and minimal decorative icons.

## Base Prompt

```text
创作一张中文彩色 AI 技术白板信息图，主题为【主题】，核心观点是【观点】。整体像老师在白板上画出的高密度技术科普海报：白色或浅米白纸面背景，粗黑马克笔中文标题，彩色模块分区，手绘箭头、编号圆点、图标和短标签。不要做成严肃企业 PPT，也不要做成照片写实。

构图选择【阶段讲义海报 / 演进对比海报 / 架构地图 / 决策框架地图 / 简单架构图】。顶部是醒目的大标题，关键词用蓝色、紫色、绿色或橙色强调，可加入黄色横幅副标题。中部使用多个圆角卡片、流程箭头、技术图标和迷你示意图讲解概念。底部加入醒目的关键结论条或总结框。

视觉元素：可爱的 AI 机器人讲解员，白色圆润机身，黑色屏幕脸，青蓝发光眼睛，蓝色耳机/天线，表情友好；技术图标包括大脑、数据库、放大镜、齿轮、火箭、云、文件夹、代码、API、锁、警告三角、勾选、网络节点。线条是手绘马克笔感，边框略微不规则，填色像彩色马克笔或轻微水彩。

配色：白底，深蓝/黑色文字，钴蓝、紫色、绿色、橙色、黄色作为模块色；限制用红色或橙色警示，优势用绿色勾选。信息密度高但层级清楚，模块之间留出白色间隔。

文字：中文手写感但要清晰，使用短句和标签；保留必要英文缩写如 LLM、RAG、Agent、MCP、API、Token、Context。
```

## Negative Constraints

```text
不要照片写实、不要3D渲染、不要极简企业PPT、不要无装饰工程图、不要米黄色复古手账风、不要只用黑白线框、不要大段难读小字、不要真实人物肖像、不要复制参考图中的签名水印或完整布局、不要让机器人变得恐怖或机械压迫。
```

## Quality Checklist

- [ ] 看起来像彩色白板技术科普海报，而不是普通 PPT。
- [ ] 顶部有强标题和明确彩色关键词。
- [ ] 选择的布局与文章内容匹配。
- [ ] 演进类文章有清楚的阶段链路、彩色分栏和底部总结条。
- [ ] 有机器人讲解员或清晰技术图标作为视觉锚点。
- [ ] 模块颜色、编号、箭头和图标帮助阅读，而不是装饰噪音。
- [ ] 白底明亮，色彩鲜明但不脏乱。
- [ ] 技术关系、阶段或架构能一眼看出。
- [ ] 文本短而清晰，英文缩写保留准确。
- [ ] 未漂移成米黄手绘知识漫画、极简工程图或商业幻灯片。
